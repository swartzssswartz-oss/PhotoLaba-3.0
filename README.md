# СВЕМА LAB :: Film Simulation Engine

## Запуск
Главная страница — `index.html`. Фото-лаборатория открывается через ссылку
«СВЕМА ЛАБ» или напрямую из `СВЕМА ЛАБ.html`. Обе страницы работают без сборки.

## Установка как приложение (PWA)
Баннер "Установить СВЕМА LAB" появляется внизу экрана автоматически.

**Важно:** это работает только если сайт открыт по **HTTPS** или на **localhost**.
Браузеры сознательно блокируют Service Worker (а без него не будет и промпта
установки) на обычном `file://` — то есть если вы просто дважды кликнули по
`index.html`, баннер либо не появится, либо появится, но кнопка "Установить"
не сработает.

Чтобы проверить локально — поднимите любой локальный сервер в папке проекта:

```bash
# Python (уже есть почти везде)
python3 -m http.server 8080
# затем открыть http://localhost:8080

# или Node, без установки
npx serve .
```

Для реального использования на телефоне — залейте папку на любой хостинг с
HTTPS: GitHub Pages, Netlify, Vercel, Cloudflare Pages — все бесплатные и
дают HTTPS из коробки.

На **iOS Safari** нативного промпта не бывает в принципе (Apple не
поддерживает `beforeinstallprompt`) — там баннер покажет инструкцию
"Поделиться → На экран «Домой»" вручную.

## Производительность на мобильных
Пока вы тащите слайдер, движок считает превью на уменьшенном буфере
(420px по длинной стороне) — быстро, без подвисаний. Через ~140мс после
отпускания автоматически досчитывается полное качество. Экспорт (кнопка
"Экспорт") всегда идёт в полном разрешении независимо от этого режима.

Рабочая копия фото и экспорт ограничены 4096px по длинной стороне: снимок
с телефона бывает 48 Мп, а каждый шаг движка держит в памяти целый кадр
(превью + ImageData на входе и выходе), и без потолка вкладка падала прямо
на загрузке. 4096px — это 12–16 Мп результата, больше любого экрана.

## Загрузка фото
На главном экране — зона "Загрузить фото": она открывает системную галерею
(только фото, без "Файлов" — так системный диалог не переключается на них по
умолчанию). Как только фото выбрано, приложение само переходит в редактор.

Принять файл можно и другими привычными способами: перетащить его на главный
экран или прямо на кадр в редакторе, либо вставить картинку из буфера (Ctrl+V).

Для RAW-файлов (.RAF/.CR2/.NEF/.ARW/.DNG и т.д.) — отдельная кнопка "Загрузить
RAW-файл" (есть и на главном экране, и в редакторе): браузер не умеет
декодировать сырые данные сенсора, поэтому из RAW вытаскивается встроенный
JPEG-превью (камера сама кладёт его внутрь файла для быстрого просмотра). Если
превью найти не удалось — покажет понятную ошибку с советом экспортировать
JPEG из RAW-конвертера.

Чтобы заново открыть то же самое фото, ничего чистить не нужно: поле выбора
файла сбрасывается после каждой загрузки.

## Кадрирование и поворот
Кнопка "Открыть окно кадрирования" — полноэкранный редактор с перетаскиваемой
рамкой (сетка третей, соотношения 3:2/1:1/4:5/16:9/9:16/2.39:1) и поворотом:
кнопки ⟲90°/90°⟳ для быстрой смены ориентации + слайдер точного выравнивания
горизонта (±45°, с автоматическим масштабированием, чтобы по углам не
появлялись пустые треугольники).

## Отмена и повтор
Кнопки ↶/↷ в шапке (или Ctrl+Z / Ctrl+Y, Ctrl+Shift+Z) отменяют и повторяют
любую правку: слайдеры, чекбоксы, селекты, текст рамки/штампа и смену плёнки.
Снимок делается до изменения, поэтому «Отменить» возвращает именно прежнее
значение, а не то же самое. Кадрирование и поворот в историю не пишутся —
это свойства конкретного фото (см. раздел про свои пресеты).

## Сохранение результата
На мобильных при экспорте картинка открывается в новой вкладке — долгий тап
по ней → "Сохранить изображение"/"Добавить в Фото" работает в любом мобильном
браузере и не зависит от того, какие приложения на телефоне зарегистрированы
как получатели Share. Кнопка "Или поделиться…" (когда доступен Web Share API)
— опциональный дополнительный способ. На десктопе — обычное скачивание файла.

## Пресеты плёнок
Все 58 пресетов (29 Ч/Б + 21 цветной + 8 спец/ИК) имеют физически осмысленные
и визуально различимые рецепты: контраст, зерно (размер/плотность/форма),
туман проявителя, halation/bloom, и отклик по каналам (Lift/Gain — тени и
света отдельно на R/G/B). У Ч/Б плёнок вдобавок свой спектральный вес
перевода в градации серого (панхром/ортохром), у цветных — цветовые сдвиги
через ту же физическую модель Film Response, а не отдельные хардкод-формулы.

## Свои пресеты
Кнопка "Сохранить как пресет" запоминает текущую полную конфигурацию
слайдеров (включая базовую плёнку, на которой основан образ) в localStorage
браузера — не привязано к конкретному фото, не требует сети. Появляются во
вкладке "Мои" в списке пресетов, с возможностью удаления. Кадрирование и
поворот сознательно НЕ входят в снимок — это свойства конкретного фото, а
не "образа плёнки".

## Структура
```
index.html
sw.js                      — Service Worker (кеш + офлайн)
assets/
  app.js                   — UI-слой
  crop.js                  — окно кадрирования и поворота
  raw.js                   — извлечение превью из RAW-файлов
  pwa.js                   — логика промпта установки
  manifest.json            — Web App Manifest
  data/film-data.js        — база плёнок (включая kind и цветовую науку бренда) + схема состояния
  engine/                  — модульный движок симуляции (11 модулей: masks, filmResponse,
                             developer, pushpull, grain, acutance, uniformity, halationBloom,
                             noise — фрактальные текстуры для дефектов, defects, core)
  styles/                  — CSS
  icons/                   — иконки приложения
```

## Обновление: RAW, LUT, экспорт, гистограмма

**RAW.** Файлы RAW (RAF, CR2/CR3, NEF, ARW, ORF, RW2, DNG и др.) проявляются по-настоящему через LibRaw в WebAssembly
(`assets/vendor/libraw/`, `assets/raw.js`): демозаик, баланс белого, матрица камеры, 16 бит → рабочая копия.
В панели «RAW-проявка» (раздел «Отклик») — экспозиция ±EV, баланс белого, восстановление светов, качество демозаика,
шумоподавление, разрешение. Если декодер недоступен, берётся встроенный JPEG-превью из файла.
Декодер работает в модульном воркере, поэтому нужен http(s): откуда угодно, где открывается сайт (GitHub Pages, локальный
сервер), но **не из `file://`**.

**LUT.** Цветовая часть движка (экспозиция, проявка, toe/shoulder, характер плёнки, бумага, тонеры, кросс-процесс, старение,
вуаль, Film Response, кривая) запекается в 3D LUT 33³ и применяется тетраэдральной интерполяцией (`assets/engine/lut.js`):
в среднем в 4 раза быстрее прямого расчёта, ошибка относительно него ≈0,3 из 255. Зерно, галация, блум, резкость,
дефекты, виньетка и хром. аберрация в LUT не входят и считаются после него. В разделе «Стиль → LUT-обработка»:
загрузить внешний `.cube` (3D, домен 0..1), смешать с движком или использовать вместо него, скачать `.cube` 65³ с цветом
текущей плёнки. Прямой расчёт без LUT включается снятием галочки; для кастомных масок и «Микрат-200» он используется сам.

**Экспорт.** PNG (без потерь), JPEG (качество 60–100), TIFF (несжатый RGB, 8 бит), размер от 1080 px до максимального.
Зерно считается в 8 бит, поэтому 16-битного TIFF нет.

**Гистограмма.** Панель на сцене (кнопка «Гист.» или клавиша `H`): RGB или яркость, процент обрезанных теней и светов.

**Про общую память WASM.** Оригинальная сборка libraw-wasm требует общую память (shared memory), которую Firefox и Safari
разрешают только на страницах с заголовками COOP/COEP (у GitHub Pages их нет). В `assets/vendor/libraw/` лежит пересобранная
без этого требования копия, результат проявки побитно совпадает с оригиналом. Подробности правок — в `NOTICE.txt` рядом.
